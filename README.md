# منصة التقويم التجريبي لمباراة التعليم – CRMEF 🇲🇦

منصة ويب تفاعلية للتحضير لمباراة التعليم في المغرب، مبنية بـ **Vite + React 19 + TypeScript (strict) + Tailwind CSS v4**، وتستخدم **Supabase** للمصادقة وقاعدة البيانات والتخزين، وتُنشر على **Vercel**.

> **قبل أي نشر:** طبّق ملف [`supabase_schema.sql`](./supabase_schema.sql) كاملاً على مشروع Supabase، ثم راجع [`DEPLOYMENT_CHECKLIST.md`](./DEPLOYMENT_CHECKLIST.md). التطبيق يعمل دون Supabase بوضع قراءة محدود، لكن المصادقة والاشتراكات والملخصات المدفوعة تحتاج قاعدة البيانات.

## ✨ المميزات

1. **محاكاة رسمية بالمعاملات:**
   - الابتدائي: العربية 6، الفرنسية 6، الرياضيات 6، العلوم 2، ديداكتيك كل مادة 3، علوم التربية 8.
   - الثانوي: مادة التخصص 20، ديداكتيك التخصص 12، علوم التربية 8.
   - حساب المعدل المرجح النهائي من 20.
2. **تقويم قبلي وبعدي:** اختبار تشخيصي قبل المراجعة أو محاكاة نهائية بعدها.
3. **تحليل ميتامعرفي:** درجة الثقة في كل جواب (`متأكد`، `متردد`، `تخمين`، `لا أعرف`)، مع رصد «وهم المعرفة» و«تخمين الحظ».
4. **مصادقة آمنة عبر Supabase Auth فقط:** لا توجد كلمات مرور محلية ولا حساب مشرف مضمّن في الكود.
5. **نموذج مدفوع (20 سؤالاً مجانياً لكل مادة):** التجريبي لا يرى إلا عينة `is_trial` (أول 20 لكل مادة) بلا إجابات؛ بعد الاشتراك تُفتح كل الأسئلة + الملخصات في سلكه. الإجابة تُتحقق منها الخادم عبر `answer_question` (الإجابة الصحيحة لا تُرسل للعميل أبداً قبل الإجابة).
6. **اشتراك مدفوع بمراجعة بشرية:** يرفع المترشح صورة الوصل إلى مخزن **خاص** (صور فقط، 5MB كحد أقصى)، ويطّلع المشرف عليها عبر رابط موقّع مؤقت.
7. **ملخصات مدفوعة محمية:** تُقرأ من جدول `summaries` وفق سياسة RLS حسب سلك المستخدم، ولا تُضمَّن في حزمة JavaScript العامة.
8. **لوحة إدارة:** إضافة/استيراد/حذف الأسئلة، ومراجعة طلبات الاشتراك — للمشرف فقط.

## 🔐 نموذج الأمان

| الطبقة | الضابط |
| :--- | :--- |
| المصادقة | Supabase Auth (بريد + كلمة مرور)، مع إلزامية تأكيد البريد |
| الدور والاشتراك | يُقرآن حصراً من جدول `public.profiles` المحمي بـ RLS — لا من `user_metadata` |
| ترقية المشرف | يدوية عبر SQL فقط: `UPDATE public.profiles SET role='admin' WHERE email='...'` |
| كتابة الأسئلة | المشرف فقط (`public.is_admin(auth.uid())`) |
| قراءة الأسئلة | التجريبي: `is_trial` فقط (20/مادة)؛ الكامل/المشرف: الكل (RLS) |
| الإجابات والشروح | `question_answers`: الكامل/المشرف فقط؛ التجريبي عبر `answer_question` بعد الإجابة |
| وصلات الدفع | مخزن `receipts` **خاص** (صور ≤5MB)، وسياسات تسمح لصاحب الملف والمشرف فقط |
| الملخصات المدفوعة | RLS: المشترك الكامل في سلكه أو المشرف فقط |
| محتوى مدفوع في الحزمة/المستودع | ممنوع: الأسئلة والملخصات تُولَّد محلياً فقط (`supabase_*_seed.sql` غير متتبع) |
| رؤوس HTTP | CSP، HSTS، `X-Frame-Options`، `nosniff`، Referrer-Policy، Permissions-Policy، COOP في `vercel.json` |
| الأسرار | لا يُسمح إلا بالمفتاح العام `VITE_SUPABASE_ANON_KEY` في متغيرات `VITE_` |

> أي حماية في المتصفح (مثل عدّاد محاولات الدخول) هي تحسين تجربة فقط؛ الحد الأمني الفعلي يفرضه Supabase وRLS.

## 🚀 الإعداد المحلي

### 1. المتطلبات
- Node.js 20+ (المشروع مُختبر على Node 22)
- مشروع Supabase

### 2. المتغيرات البيئية
انسخ `.env.example` إلى `.env.local`:

```env
VITE_SUPABASE_URL=https://<project-id>.supabase.co
VITE_SUPABASE_ANON_KEY=<anon-or-publishable-key>
```

ثم تحقق:

```bash
npm run check:env
```

### 3. تهيئة قاعدة البيانات
1. افتح **Supabase Dashboard > SQL Editor**.
2. نفّذ محتوى [`supabase_schema.sql`](./supabase_schema.sql) كاملاً (هيكل + أمان فقط، بلا بذور — البذور مدفوعة وغير متتبعة). الملف آمن لإعادة التشغيل، وينشئ:
   - `profiles` (الدور والاشتراك)
   - `questions` (نصوص فقط) + `question_answers` (الإجابات المدفوعة)
   - `subscription_requests`
   - `question_progress` + دالتا الكوطة والإجابة الخادمية
   - `summaries` + مخزن `receipts` الخاص وسياساته
3. ولّد البذور محلياً ونفّذها (ملفات غير متتبعة — لا ترفعها أبداً):
   ```bash
   npm run seed:questions   # → supabase_questions_seed.sql (2,284 سؤالاً + الإجابات + تعليم العينة)
   npm run seed:summaries   # → supabase_summaries_seed.sql (19 ملخصاً)
   ```
   ثم نفّذ الملفَين في SQL Editor بعد الخطوة 2. يتطلب ولّد الأسئلة وجود `questions_seed.json` محلياً (مصدر البنك الخاص — غير متتبع).
3. فعّل حساب المشرف مرة واحدة:

```sql
UPDATE public.profiles
SET role = 'admin'
WHERE email = 'ضع-بريد-المشرف-هنا';
```

4. (اختياري) أدرج الملخصات المدفوعة محلياً:

```bash
npm run seed:summaries   # ينتج supabase_summaries_seed.sql غير متتبع
# ثم نفّذ الملف الناتج في SQL Editor
```

### 4. التشغيل

```bash
npm install
npm run dev
```

### 5. البناء والفحص

```bash
npm run lint
npm run build
npm run preview
```

## ☁️ النشر على Vercel

1. اربط مستودع GitHub بمشروع Vercel (إطار العمل: Vite).
2. أضف متغيرات البيئة في **Settings > Environment Variables**:
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`
3. تأكد أن `supabase_schema.sql` طُبّق قبل النشر.
4. اضغط **Deploy** ثم نفّذ فحوصات ما بعد النشر في [`DEPLOYMENT_CHECKLIST.md`](./DEPLOYMENT_CHECKLIST.md).
5. أضف نطاق Vercel إلى **Supabase > Authentication > URL Configuration** (Site URL + Redirect URLs) حتى تعمل روابط تأكيد البريد واستعادة كلمة المرور.

## 📁 هيكل المشروع

```
src/
├── components/        # الواجهات (الاختبار، الإدارة، الاشتراكات، الملخصات...)
├── context/           # AuthContext: المصادقة والملف الشخصي والاشتراك والتقدم
├── data/              # (أُزيل: البنك المدفوع يُجلب من Supabase — لا بنك مدمج في الحزمة)
├── lib/               # عميل Supabase، التحقق، أدوات الأمان
├── types.ts           # الأنواع والمواد والمعاملات
├── App.tsx            # التوجيه بين التبويبات وتحميل المكونات الثقيلة
└── main.tsx           # نقطة الدخول + ErrorBoundary

scripts/
├── generate_supabase_sql.cjs   # تحديث بذور الأسئلة فقط
├── build_summaries_data.cjs    # يبني مصدر الملخصات في scripts/seed-data (غير متتبع)
├── export_summaries.mjs        # يحوّل الملخصات إلى SQL
├── check_env.mjs               # فحص متغيرات البيئة (يُشغَّل تلقائياً قبل البناء والتطوير)
├── analyze_questions.cjs       # إحصاء بنك الأسئلة
└── generate_*.cjs              # سكريبتات توليد البنك (مرجع تاريخي، لا تُشغَّل إلا عند تحديث البنك)

questions_seed.json             # (محلي غير متتبع) المصدر الخاص لبنك الأسئلة — يولّد منه supabase_questions_seed.sql

supabase_schema.sql    # المخطط الآمن + بذور الأسئلة
vercel.json            # رؤوس الأمان + SPA rewrites
```

## ⚠️ ملاحظات تشغيلية

- **بذور الأسئلة شرط للكوطة الخادمية:** دالة `record_question_progress` تتحقق من وجود السؤال في جدول `questions`. لذلك يجب تطبيق بذور الـ 2,284 سؤالاً كاملة، وإلا لن يُسجَّل تقدم الأسئلة غير الموجودة في القاعدة.
- **المحتوى المدفوع لا يُرفع للمستودع:** `scripts/seed-data/` و`supabase_summaries_seed.sql` مدرجان في `.gitignore`.
- **إعادة النشر إلزامية:** أي نسخة قديمة منشورة قبل هذه التغييرات قد تحتوي بيانات دخول قديمة؛ يجب إعادة النشر والتحقق من الحزمة.
- **لا توجد اختبارات وحدات بعد:** يوجد فحص CI للبناء وlint في `.github/workflows/ci.yml`.
